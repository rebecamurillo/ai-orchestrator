# Blind hunter findings — story 1-1
Returned by a context-free reviewer agent. 30 findings.

- **`DATABASE_URL` is typed `str`, so the Postgres password prints in `repr(Settings())`** (`backend-api/src/orchestrator/infrastructure/settings.py`). Verified: `repr()` yields `database_url='postgresql+psycopg://orchestrator:change-me@postgres:5432/orchestrator'`. `test_secret_values_never_appear_in_repr` misses it because `DATABASE_URL`/`POSTGRES_PASSWORD` are absent from `SECRET_VARIABLES`, so the one test guarding hard rule 5 ("secrets never appear in code, tests, logs") passes over the one field that leaks.
- **`log_level` accepts any string and then fails open.** `Settings(log_level="bogus")` validates, and `configure_logging` does `getLevelNamesMapping().get(level.upper(), logging.INFO)` — a typo'd `LOG_LEVEL` silently runs at INFO. A `Literal["debug","info","warning","error","critical"]` (or a raise on unknown names) is missing, and the fallback contradicts the repo's own "no gate passes silently" stance.
- **Numeric settings have no bounds.** `Settings(max_active_runs=0)` validates (verified) — the global queue would accept zero concurrency, which AD-12 treats as a live invariant; `backend_api_port` and `dbos_application_version` are likewise unconstrained `int`. No `Field(ge=1)`/`PositiveInt` anywhere.
- **`scripts/check_env_contract.py` is outside every gate it enforces.** `make lint` runs `uv run --directory backend-api ruff check .` / `mypy …`, so the working directory is `backend-api/` and the root `scripts/` tree is never linted, format-checked, or type-checked (confirmed with `ruff check --show-files .`). The repository's only root-level Python module is the one module no gate looks at.
- **The check's success message miscounts what it compared.** It prints `env contract: {len(settings_variables())} variables agree` — "25 variables agree" — while the contract file declares 31 (6 allowlisted). The number reported is the size of one side, not of the agreement.
- **Two env-file parsers with different rules and no shared source.** `check_env_contract.env_example_variables` and `tests/unit/conftest.parse_env_example` re-implement the same format: the conftest one truncates values at `#`, the script one does not; neither handles `export ` prefixes, quoted values, or trailing-`#` inside a legitimate value. Both build a `set`/`dict`, so a variable declared twice in `.env.example` collapses silently instead of being reported.
- **A mis-cased contract line defeats the check in both directions.** `env_example_variables` skips any name failing `name.isupper()`, so `Log_level=…` is invisible to the gate; and because `Settings` uses `case_sensitive=False` with `extra="ignore"`, that same line would still be consumed at runtime. The exact drift AD-20 exists to catch passes green.
- **The allowlist is asserted against itself.** `COMPOSE_ONLY_VARIABLES`' docstring promises "each one that is added here must be a variable no backend module reads", but nothing verifies that; `test_the_allowlist_covers_exactly_the_non_backend_contract_variables` restates the same six literals the module defines, so the test only proves the constant equals itself. Adding a seventh entry to smuggle a backend variable past the gate requires editing two places that always agree.
- **Nothing checks that `.env.example` holds only placeholders.** The `!.env.example` negation deliberately keeps this one env file tracked, and the story's acceptance criterion is "no real secret is committed" — but no test or lint step asserts the values match a placeholder shape. The story's own verification grep (`(ghp_|sk-)[A-Za-z0-9]`) also matches the substring "risk-", so it returns hits on unrelated prose and cannot be used as a clean signal.
- **The `.gitignore` rules themselves are untested.** `.env` / `.env.*` / `!.env.example` is order-dependent and silently breakable (move the negation above the pattern and the contract file disappears from the repo). A three-line `git check-ignore` test would pin the behaviour the story lists as acceptance; there is none.
- **`infrastructure/logging.py` has no test.** The story requires "structlog JSON to stdout at `LOG_LEVEL`", yet no test asserts the output is JSON, goes to stdout, carries the timestamp/level processors, or honours the configured level. `main()` is uncovered too — only `create_app` is exercised.
- **Only half the log stream is structured.** `structlog.PrintLoggerFactory` bypasses stdlib logging entirely, so uvicorn/FastAPI records travel through `logging.basicConfig(format="%(message)s")` and land on the same stdout as unstructured plain text. Without a `ProcessorFormatter` bridge, "structlog JSON to stdout" holds only for structlog call sites, and log consumers will see a mixed stream.
- **`cache_logger_on_first_use=True` plus configuring from the app factory.** `create_app` calls `configure_logging`, so building an app is a global side effect, and because loggers are cached on first use a second call cannot change the level of anything already bound. Every test that constructs an app reconfigures process-wide logging; the composition-root concern belongs in `main()`, not in the factory.
- **The `# noqa` codes suppress rules that are not enabled.** `S104` (`main.py`), `S603` (three test modules) and `DTZ001` (`test_clock_fake.py`) belong to flake8-bandit and flake8-datetimez; `select = ["E","F","I","B","UP","PL","C90"]` enables neither, and `RUF100` is not on to flag the dead suppressions. They read as considered-and-waived security findings while nothing is actually being checked — binding to `0.0.0.0` in particular is unexamined.
- **`backend-api/AGENTS.md`'s "Checkable limits" are not checkable.** "A module is ≤ 400 lines" has no rule behind it; "a function ≤ 50 lines (ruff `PLR0915`)" cites a rule that counts *statements*, not lines, and no `[tool.ruff.lint.pylint] max-statements` is set; "No `print`" cites nothing (`T20` is not selected); "100% branch coverage on `domain/` and `application/`" has no coverage invocation or threshold anywhere, though `pytest-cov==7.1.0` is a declared dev dependency that nothing uses.
- **Gates can rewrite the lockfile they exist to pin.** `make lint`/`make test` call `uv run` without `--locked`/`--frozen`, so a `pyproject.toml` edit lets a gate silently re-resolve and modify the committed `backend-api/uv.lock`. `backend-api/AGENTS.md` documents `uv sync --locked` but no target enforces it, and there is no `.python-version`, so the interpreter a gate runs on is unpinned despite "reproducible gates" being the stated purpose of committing the lock.
- **Three descriptions of the same gates already disagree.** Root `AGENTS.md` says `make lint` runs `eslint · prettier --check · tsc` and `make test` runs vitest; `README.md` says those arrive "from story 1.3"; the `Makefile` runs neither, and `prettier` appears in no other file. `make openapi`'s AGENTS.md description ("fails on drift") documents behaviour that does not exist. The constitution states the end state as present tense with no not-yet marker, while the Makefile it points at is the only artifact honest about what is missing.
- **Hard rule 6 cannot be satisfied by any current story.** "A story is done only when `make lint test e2e-api e2e-ui` pass" — but `e2e-api` and `e2e-ui` exit 1 by design until 1.2/1.3. The definition of done contradicts the Makefile it references, and nothing in either file reconciles them.
- **The constitution names root artifacts that do not exist.** `contracts/openapi.json`, `templates/*.yaml`, `scripts/harness/*.sh`, `docker-compose.yml`, and the entire `web-client/` component are described as "shared at the root" / a live component; none are present (verified). `scripts/harness/_common.sh` is cited as the authority for `HARNESS_ENV_CONTRACT`, and readers are told to "read the `AGENTS.md` of the component you are changing" when `web-client/AGENTS.md` does not exist.
- **README's quickstart leads with a command that exits 1.** The *Running it* block opens with `cp .env.example .env` / `make up`, and the caveat that most targets report `not available until story <id>` sits eight lines below the code block. The first runnable instruction a new contributor copies fails.
- **"Unit" tests shell out to `make`, to `lint-imports`, and copy the source tree.** `test_makefile.py` runs `make <target>` from inside pytest — which `make test` itself invokes — so a unit test recursively drives the build tool and requires `make` on `PATH`; `test_layering.py` `copytree`s `src/` and spawns `lint-imports` twice. Both live under `tests/unit`, which the Makefile comment advertises as "no Postgres, no network", and there is no marker separating them from the fast tests.
- **`test_layering.py` guesses the linter path and wipes the subprocess environment.** `LINT_IMPORTS = Path(sys.executable).parent / "lint-imports"` assumes console scripts sit beside the interpreter (false on Windows, where the name also needs `.exe`, and in split script layouts), and `env={"PATH": …, "PYTHONPATH": …}` drops everything else — no `HOME`, `TMPDIR`, or `SYSTEMROOT`. There is no skip/xfail guard if the executable is absent, so the failure mode is a `FileNotFoundError` rather than a readable message.
- **`test_env_contract.py` mutates `sys.path` at import time and imports a `conftest` as a module.** `sys.path.insert(0, REPO_ROOT / "scripts")` is a session-wide side effect triggered by collecting one test file, `scripts/` has no package marker, and `from tests.unit.conftest import …` imports under a second name a module pytest also loads as a conftest. A future `scripts/` module colliding with a stdlib or site-packages name would break collection for the whole suite.
- **Unit tests assert on placeholder values from the contract file.** `test_settings.py` asserts `log_level == "info"`, `max_active_runs == 2`, `local_models == ["local-coder","local-general"]`, `work_dir == "/work"` — all read out of `.env.example` by the `env` fixture. Editing a placeholder or a default in the contract breaks tests that have nothing to do with it; the fixture's job (every variable is present) is conflated with the assertions' job (these specific values).
- **`conftest.env`'s `delenv` loop is dead code.** It deletes exactly the names the `setenv` loop immediately below reassigns, so it changes nothing. What it looks like it should do — clear *other* `ORCHESTRATOR_*`/`LITELLM_*`/`LANGFUSE_*` variables an operator may have exported, which `case_sensitive=False` would otherwise let leak into a test — it does not do.
- **`CLAUDE_ALLOWED_TOOLS` is comma-split with no escaping.** `_split_csv` on a value of tool patterns works only because today's value happens to contain no comma inside its parentheses; `Bash(git add, git commit)` would silently split into two malformed permissions. No test covers a value containing a comma, a quote, or nested parentheses.
- **`.env.example` states the Postgres password twice.** `POSTGRES_PASSWORD=change-me` and the same literal embedded in `DATABASE_URL`; nothing checks the two agree, so a real `.env` with a changed password silently leaves the application connecting with the old credential while compose provisions the new one.
- **`/healthz` returns a bare `dict[str, str]` with no `response_model`.** AD-3 makes the generated OpenAPI document the sole source of the web-client's payload types, so this route contributes a free-form object schema. `test_healthz` asserts only that `/healthz` appears in `paths` — the response schema, which is the part downstream code generation consumes, is unasserted, as is the fact that FastAPI serves `/docs` and `/redoc` unauthenticated while AD-4 makes the bearer token the single credential.
- **`scripts/check_env_contract.py` advertises standalone execution it does not have.** It carries a `#!/usr/bin/env python` shebang, is not executable (`-rw-r--r--`), and imports `orchestrator.infrastructure.settings`, so it only runs inside the backend virtualenv. Nothing in the file or in `README.md` says so; the Makefile encodes that coupling implicitly via `uv run --directory backend-api python ../scripts/…`.
- **Scaffolding the rest of the change assumes is missing.** There is no `backend-api/tests/e2e/` although `testpaths = ["tests"]` and `backend-api/AGENTS.md` documents `uv run pytest tests/e2e -q`; no `py.typed` in `src/orchestrator/` despite a fully annotated, hatchling-packaged distribution; and `.gitignore` omits `.import_linter_cache/` (present in the tree, ignored today only because import-linter writes its own `.gitignore` inside it), `.coverage.*`, and the Playwright outputs (`test-results/`, `playwright-report/`) that `make e2e-ui` will produce.
