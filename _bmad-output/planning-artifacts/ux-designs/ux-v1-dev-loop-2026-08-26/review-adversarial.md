# Adversarial Review — v1 experience update 2026-09-15

Scope: EXPERIENCE-v1.md (§2.2, §2.3, deltas 20–26) against DESIGN.md, sprint-change-proposal-2026-09-14 (F2, F3, §5), .memlog.md, prd.md, and the two `.working` artboards. Memlog decisions treated as authoritative.

## Verdict

The new §2.2 and §2.3 are internally coherent and land almost everything F2/F3 promise, and the diagram dialect is stated carefully where it was written. But the rework left three stale passages elsewhere in the same document (Runs history rows, the Templates cross-reference, the naming rule) that now contradict the new sections, and the colour dialect has two holes (`SKP`/`CAN` have no border colour; "DON — green throughout" collides with the frozen skipped-is-never-green convention). Both mocks are close to the spine, except that StepRunDetail.html leaks the diagram-only blue onto an off-diagram surface — the exact mistake the dialect paragraph exists to prevent.

## Contradictions

- **high** "Rows link to the run detail scrolled to that path" (§4 Runs, history table) vs "Reached from a leaf diagram node, a Steps-tab row, or a Runs-history row" (§2.3) and "The 09-02 'click switches to DETAIL scrolled to the row' retires" (delta 23) and F2 ("Clicking any step row, diagram node, or history row opens a Step-run detail", proposal §4 F2) — the same click cannot open two different pages; worse, "scrolled to that path" no longer resolves at all, because the Steps table now lives behind a non-default tab (§2.2 tabbed region, GATE RECORD is the default). *Fix:* in §4, change the sentence to "Rows link to that step's step-run detail (§2.3)."

- **high** "`DON` — green throughout, each epic box carrying its compare link" (§2.2 diagram States) vs "`skipped` … always the word, never green" (State vocabulary, SKP row; root AGENTS.md conventions: "`skipped` and `unvalidated` are words on screen, never green") — a done run can contain skipped stories and epics (Operator workflow step 6 lists them), and PRD FR-29's aggregate rule yields `SKP` boxes ("`SKP` when all are skipped, else `DON` when all are done or skipped"), so a done run's diagram cannot be green throughout without painting a skipped box green. The dialect compounds this: its five states (done/running/error/waiting/scheduled) assign no border colour to `SKP` nodes or to the `CAN` root at all — a front-end dev must invent one. *Fix:* in the dialect and §2.2 Colour, add "skipped and cancelled: `{colors.line}` grey border, word token only — never green"; change the DON state line to "green throughout except skipped boxes, which stay grey".

- **medium** "A step is never named two ways on one screen" (Naming rule) vs §2.3 header, which mandates both on one screen ("label (`epic 1 · story 4-1 · build`), the **path** in full"), and vs §2.2, where the diagram footer and the stop-zone banner print the label while the gate record (default tab, simultaneously visible) and Steps tab print the path for the same step. The rule was written when label contexts and path contexts were different screens; the merge broke it. *Fix:* rescope the sentence to "…never named two ways in one component; a detail header may pair label and path, in that order."

- **medium** "**stop zone** (exists only when the run needs you or failed)" (§2.2 layout line) and "the section does not exist otherwise" (delta 20) vs "`DON` — the stop zone's place holds a one-line summary…" and "`CAN` — grey banner, `cancelled by operator at …`" (§2.2 Other states) — a `DON` or `CAN` run neither needs you nor failed, yet §2.2 puts content in the zone's place; meanwhile the layout rule says the diagram then sits directly under the header, leaving that content nowhere. A dev cannot decide whether the region renders. *Fix:* state it as one rule: "the top zone renders for needs_you/failed (full stop body), done (one summary line) and cancelled (one grey line); it does not exist for queued/running."

- **medium** "Resolving a stop never requires a scroll or a tab" (§2.2 stop zone) vs the terminal-session state: the only statement of *why* Answer/Continue/Skip/Retry are disabled — and, per PRD FR-21, the *Release* control that re-enables them — is "the line under the command block" (§2.2 last bullet), and the command block lives in the SESSION tab (§2.2 tabbed region). While a session is in progress, resolving the stop requires opening that tab. *Fix:* when a session is in progress, repeat the one-line reason with the *Release* control inside the stop zone, next to the disabled actions.

- **medium** "Diagram rendered from the backend graph (left-to-right like 2.3: node per step…)" (§5 Templates) vs §2.3, which is now the Step-run detail and contains no diagram — the cross-reference points at the retired Run-diagram surface's old section number. (Delta 18's "like the run diagram" still resolves; §5's "like 2.3" does not.) *Fix:* change "like 2.3" to "like the run diagram (§2.2)".

- **medium** Frontmatter "aligned-to: ../../mvp/prd.md (2026-09-02, FR-1..FR-33)" and `status: final` vs PRD FR-23 ("in a detail view or a diagram view (FR-29)"), FR-29 ("Clicking a node scrolls the detail view to that Step's row", "The diagram is read-only") — the spine retires the separate diagram view and makes leaf clicks navigate to a new page, which FR-29's testable consequences forbid as currently written. The proposal makes the `bmad-prd` pass a gate (proposal §5, §7) but it has not run; until it does the spine and the document it claims alignment to cannot both be true. *Fix:* annotate the frontmatter: "FR-23/FR-29/NFR-6 deltas of the 2026-09-14 proposal pending the bmad-prd pass", mirroring the pending-artboards note already there.

- **medium** DESIGN.md "a detail body is capped at `{spacing.detail-max}` 940px" (Layout & Spacing; unchanged, and per memlog "stays the visual authority") vs §2.2's full-width bottom tabbed region and centerpiece diagram with a 300px summary column (the mock uses 1440px) — the spine's own contract is "where it disagrees … this one wins for v1 **and the reason is stated**" (intro), and delta 8 stated exactly such a width override for the board, but no delta states one for the run detail. *Fix:* add a delta line: "Run detail and step-run detail widen to the board's 1440px fluid width; 940px `detail-max` applies only to prose blocks (question, answer, stop body)."

- **low** Test-id `wf-diagram-node-<path>` (Test-ids) — the document now has two machine path spellings (bracket `epics[0].stories[3].build`, Naming rule; dot-index `epics.0.stories.3.build`, §2.3 route) and the test-id grammar does not say which; brackets are hostile in selectors. *Fix:* state "test-ids use the dot-index form, same as the route".

- **low** "Content never moves under the cursor: a card changing column is a state swap on the next poll, not an animation" (§ Refresh, global) vs §2.3 log follow: "new lines append on the poll interval, the view keeps the tail in sight" — a followed log moves content under a cursor hovering it by design; the stated escape (scroll-up pauses) covers scrolling, not the rule itself. *Fix:* add the exception where the Refresh rule is stated: "exception: a followed log tail (§2.3), which is what the follow/pause control governs."

- **low** DESIGN.md "This left border is the *only* place a signal colour extends beyond 7px" (alert-banner) and "No other signal colour extends beyond its chip and token" (Colors) vs the diagram dialect's per-node coloured borders — the spine's override clause covers the disagreement, but DESIGN.md remains "the visual authority" (memlog) and is unamended, so a dev reading DESIGN for colour rules gets the wrong answer. *Fix:* one line in the spine's dialect paragraph: "this amends DESIGN.md's 'only place a signal colour extends beyond 7px' sentence, on this surface only."

## Dropped promises

Checked against F2 and F3 line by line: cursor paging, live follow on the poll interval, raw download, dispatch + retry prompts per attempt, every-step-kind logs, AD-1 proxy delivery, model in the header, artifact modal with rendered/highlighted/raw + download, iteration boxes with `k/n`, level-by-level expansion — all present in the spine. The proposal-vs-spine deviations that exist (gate record as a tab, not full-width; click-only expansion, no hover; stories strip kept) are explicit memlog operator decisions, not drops. One gap:

- **medium** "full-viewport log" (memlog, F2 surface decision: "Bookmarkable, survives reload mid-tail, full-viewport log") — §2.3 says only "in an inset command block, cursor-paged", stating nothing about height, and the mock caps it at 300px. A memlog decision the spine fails to state is a finding against the spine. *Fix:* add to §2.3 Log: "the block fills the remaining viewport height — the log is the page's main element."
