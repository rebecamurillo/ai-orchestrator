# v1 Experience — one operator, one dev loop

`DESIGN.md` still owns colour, type, spacing, shape and component appearance. This document owns **what v1 shows, when, and what it asks of the operator**. Where it disagrees with the 2026-08-25 spine, this one wins for v1 and the reason is stated. Updated 2026-09-02 to the PRD that followed the architecture spine: runs are planned up front, templates compose (`initiative` → `epic` → `story`), credentials are instance settings, and every stop is one row of the PRD's §4.6 Stop table.

## Attention model (the rule every screen obeys)

The brief asks for "epurated" screens where attention is driven to warnings, blocking steps and running work. Instrument-dark already says *colour is signal only*; v1 narrows the signal set to three hues and one rule:

| Hue | Token | Means | Where it may appear |
|---|---|---|---|
| green `{colors.signal-qa}` | `RUN` | a step is executing right now | chip + token, the "Running" column header |
| amber `{colors.signal-blocked}` | `BLK` `CHK` | the machine stopped and **needs you** — every Stop kind of the PRD §4.6 table; `CHK` for a checkpoint, `BLK` for all others | chip + token, the "Needs you" column header, a 2px left rule on the card / alert banner, an aged wait, the one warning line in a readout |
| red `{colors.signal-infra}` | `ERR` | **Run:** `failed`, terminal (baseline non-zero, `on_fail: fail`, parked 30 days) — nothing will proceed, no Retry. **Step:** the row that errored, which usually sits inside an amber `BLK` run | chip + token, a 2px left rule, the failing command's exit line |
| grey `{colors.text-tertiary}` / `{colors.text-secondary}` | `QUE` `DON` `SKP` `CAN` | planned or queued, done, skipped, cancelled | everything else |

**The rule:** on any card or row, exactly one element carries a signal colour — the reason it needs you. If nothing needs you, the screen has no amber or red pixel: a *declared* human gate on a template node or a future row is the word `human` and a hairline in `{colors.line-strong}`, never amber; a configuration statement (`log_prompt_content` sends source code to Langfuse) is secondary text, never a warning line. Words carry the state (`blocked`, `skipped`, `exit 1`, `unvalidated`, `provisional`); colour only reinforces. The one tolerated pair is a `BLK`/`CHK` card older than 48 h: its token and its age are both amber (they say the same thing).

Dropped from v1: the six per-escalation-type colours (BGT, RWK, INF, CRT). Budget halts and rework are `BLK` with the reason in words.

## Information architecture

| # | Surface | Route | Purpose |
|---|---|---|---|
| 1 | Login | `/login` | Enter the operator token. |
| 2 | Workflows (home) | `/` | Board of runs by status. Where is everything; what needs me. |
| 2.1 | New workflow | `/workflows/new` | Bind a template's inputs, see pre-flight and the whole plan, start. |
| 2.2 | Run detail | `/workflows/:runId` | One run: alert, question + answer, planned steps, stories, artifacts (with editor), cost, links, actions. |
| 2.3 | Run diagram | `/workflows/:runId?view=diagram` | The same run as a left-to-right tree with a status token per node: what ran, where it is, what is scheduled. |
| 3 | Projects | `/projects`, `/projects/:id` | Projects, context, repositories, method readiness, trajectories export. |
| 3.1 | New project | `/projects/new` | Form + live clone check. |
| 4 | Runs | `/runs` | Every attempt: engine queue (top) and history (below). |
| 5 | Templates | `/templates/:name/:version` | YAML editor + rendered diagram + inputs; versions and callers. |

No new route: a `repo-init` run and a harness readiness run are ordinary runs on the board and in run detail.

**Shell.** Fixed 172px rail: *Workflows* (count + "n need you" in amber when n>0), *Runs*; Configure: *Projects*, *Templates*. Footer readout: `2 running · 1 queued / 2 need you / updated hh:mm:ss · refresh`. No notifications surface — "Needs you" is a column and a rail count. **A failed fetch** replaces the surface with a full-surface readout: the failed request (method, path, status) in a command block and a *Retry* control; nothing else moves.

**Depth.** Board → run detail is the maximum. New workflow is a page, not a modal (up to eleven fields plus a pre-flight readout and the plan, must be bookmarkable and survive a reload). The only modal is the destructive confirm for *Cancel run*.

**Refresh.** Polling every 5 s while anything is `RUN`, 30 s otherwise; the footer states the last update. Content never moves under the cursor: a card changing column is a state swap on the next poll, not an animation.

## Naming rule: label and path

Every planned step has a **path** (`epics[0].stories[3].build`) and a **label** (`epic 1 · story 4-1 · build`). Detail contexts that never truncate — the Steps table, the gate record, the Runs history — print the path. Single-line contexts — cards, the LIST row, the Stories strip, the diagram footer, banners — print the label. A step is never named two ways on one screen.

## Operator workflow (Flow.dc.html)

1. **Login** — token once per 30 days.
2. **Projects → New project** — name, context text, context file paths, agent env vars (masked after save), `log_prompt_content` switch with its plain statement, one or more repositories with `default_branch`, package manager, `test_globs` (default shown: `tests/**`, `**/*.test.*`, `**/*.spec.*`), `install_command`, `quality_gate_command` (optional), `unit_test_command` (optional). No token field: the form states that the GitHub token and the gateway key are instance settings. **Save runs the clone check** per repository: `git ls-remote`, shallow clone, default branch exists, method version found in `_bmad/`. A failing repository does not block save: its row reads `failed` with the verbatim git output and a one-line fix (for a token without access: "the instance's GitHub token has no access to this repository"), and no run can start on it until the check passes; *re-run check* sits on the row. A repository whose method is `missing` or `outdated` offers *Initialise repository*.
3. **Workflows → New workflow** — template (`initiative` latest pre-selected; `epic`, `repo-init`; `story` is not offered), project, repository, base branch, then the inputs that template declares (`initiative`: initiative folder; `epic`: working branch + spec folder), harness (from the readiness list: `enabled` or `disabled: {check}`), model (harness default), budget, *re-review done stories* (off), manual estimate (optional). **Pre-flight** re-runs on every change: origin reachable, base branch exists, each branch the plan will check out exists / will be created / is held by another run, `epics.yaml` parses (epics, branches, spec folders), every `stories.yaml` parses (count, id rule), checkpoints declared (warning, never blocking), `SPEC.md` in every spec folder, harness enabled, `_bmad/` at the pinned version (fix: `run Initialise repository and merge its branch`), existing story files with statuses, clone check not failed. A red line disables *Start run* and states the fix. **What will run** is the whole plan. *Start run* persists the plan and enqueues: it starts immediately if the repository is free, else queues behind the run holding it — the button's note names that run.
4. **Workflows board** — walk away. Come back: green is running, amber needs you, red failed. The card says the label of the current step (`epic 1 · story 3-2 · build · claude · 00h 42m`) and the progress (`1/2 epics · 5/8 stories · 1 link`). Open a card and flip to **DIAGRAM** to see the whole run as a tree — what ran, where it is, what is scheduled.
5. **Run detail** — the banner names the Stop and the body follows the Stop table below: for a blocked story the question at 14px, an **Answer** box, *Resume with answer*; for a checkpoint the story spec file inline with *Continue* and *Reject with a reason*; for an errored step the failing output with *Retry*. Every stop also offers the skips it admits, *Cancel run*, and — while parked — inline editing of the spec folder files. Secondary: the resume command block (Claude, Codex; it execs into the `backend-api` container, and while a terminal session is in progress the other actions are disabled until *Release*, or until the server sees the story `done` and resumes on its own).
6. **Done** — `DON` card with `2/2 epics · 8/8 stories · 2 links`; the summary lists one compare link per epic and any skipped stories or epics beside them. Opening the pull request and merging are the human's, in GitHub.

## Screens

### 1 · Login (`Login.dc.html`)
Centered 400px panel: brand, `ACCESS TOKEN` input, *Enter*, one hint line (where the token comes from, cookie lifetime). Rejection replaces the hint with `token rejected — n attempts left` in red; after the fifth failure the line reads `too many attempts — try again in 15 min` and the input is disabled (COULD).

### 2 · Workflows board (`Main.dc.html`)
- Bar: title, count readout (`7 runs · 2 need you · oldest wait 2d 04h`), filter, project segmented filter (query string), BOARD/LIST toggle, *+ New workflow*.
- Five equal columns, never collapsing: **Queued · Running · Needs you · Done · Failed**. Header counts. The Running header is green, the Needs-you header amber; all others grey. `cancelled` runs sit under Failed with the grey `CAN` token and the word `cancelled`.
- Card, fixed order: chip + token (+ harness name right, tertiary) · current branch · project · repository · current or last step **label** · progress `n/n epics · m/m stories · k links` (the epic figure omitted for an `epic` run; a `repo-init` or readiness run shows `repo-init` / `readiness` in place of progress) · template name and version · age. Blocked/failed cards carry the 2px left rule. Aged waits (>48h) turn the age amber.
- Cards are not draggable; status is computed. Whole card → run detail.
- Empty column: `—` placeholder, header count 0. Empty board: `NOTHING RUNNING` + what is queued + link to New workflow. First run: `NOTHING REGISTERED` → Projects.
- LIST toggle: the same data as record rows (token · project · repository · branch · step label · progress · age) for when the board has more than ~20 cards.

### 2.1 · New workflow (`NewWorkflow.dc.html`)
Two columns: form (left, 190px labels) and **Pre-flight** + **What will run** (right). The form is template-dependent: choosing a template swaps the input rows below *base branch* for the ones it declares. The harness row is a list, one line per harness: name, `enabled` or `disabled: {check}` in words, last readiness time, and a *re-run readiness* link; a disabled harness cannot be selected. Pre-flight lines are `ok / ! / x / —` words in the first column, never icons. "What will run" is the plan as a dense table — `path · kind · gate` per row, loops expanded to the parsed epic and story counts, the first row `plan · plan.check`, already-done stories as `skipped · already done` unless *re-review* is on — the operator sees exactly the rows the run will execute. Decision bar under the form: *Start run* (primary), *Cancel*, one note about queueing that names the holding run.

### 2.2 · Run detail (`RunDetail.dc.html`)
- Header: crumb, chip + token + branch + age of the current state, meta line unabridged (project · repository · base · initiative or spec folder · template version · harness · started · worktree path).
- **Alert banner** only when the run needs you or failed: token, the Stop's reason text verbatim (`verify failed 2/2`, `protected path modified: tests/api/test_runs.py`, `budget $41.20 / $40.00`), right-aligned progress + spend.
- Left column, in order: the Stop body (below) → **Or continue in the session** (command block, copy, session lifetime; hidden for `local`) → **Steps** table (`path · kind · gate · status · time · harness · cost`), every planned row present from the start, `planned` rows as `QUE`, the current row promoted to primary text, a row with more than one attempt showing the latest and `· 3 attempts`. Gate column prints `liveness / deterministic / human / unvalidated` as words; status prints `skipped · already done`, `skipped · skipped by operator`, `skipped — no quality_gate_command` where it applies; nothing in these two columns is ever green.
- Right column: **Stories** strip (`n/m` per epic, one cell per story labelled by id: done filled, current amber, future hollow, skipped struck) → **Artifacts** tree at spec-folder scope with changed-since-last-opened chips; while the run is parked (and no terminal session is in progress) a file opens in an inline editor (Markdown, YAML) with *Save* — the hint under it says `saved as commit "spec: operator edit (orchestrator)" on {branch}`; `stories.yaml` and `epics.yaml` open read-only with the line `planned at {sha} — start a new run to change the list` → **Cost & trace** kv (spent/budget ratio, tokens, wall-clock, your active time, Langfuse trace link, the epic compare links, branch link); a figure not yet confirmed by the gateway carries the word `provisional` → **Gate record** (append-only; one line per event: time · path · event · actor · text; events are the Stop kinds, the signals and `start / done / failed / cancelled`).
- **Stop bodies and actions** (the PRD §4.6 table, rendered):

| Stop (banner) | Body in place of the Question | Primary | Also offered |
|---|---|---|---|
| `blocked` | the whole `## Auto Run Result`, agent attribution eyebrow, amber rule; **Answer** textarea with the hint stating the mechanism (archived to `stories/.answers/{id}-attempt-{n}.md`, story re-planned with the answer; edit `SPEC.md` on the branch when the gap is in the spec) | *Resume with answer* | *Skip story* · *Skip epic* · *Cancel run* |
| `spec checkpoint` / `done checkpoint` | the planned story file inline (spec) or the story's summary (done) | *Continue* | *Reject with a reason* (spec only; a textarea, same mechanism as Answer) · *Skip story* · *Skip epic* · *Cancel run* |
| `verify failed 2/2`, `re-baseline failed after skip` | the failing command and its last 40 lines in a command block | *Retry* | *Skip story* · *Skip epic* · *Cancel run* |
| `budget {spent} / {budget}` | the cost kv promoted; a numeric *new budget* field | *Raise budget* | *Cancel run* |
| `timeout {path} after {n} min` | the last 40 lines of the attempt log | *Retry* | *Skip story* · *Skip epic* · *Cancel run* |
| `push rejected`, `sync: branch diverged` | the git output; a line: `resolve on the remote, then Retry — Retry fetches first` | *Retry* | *Skip epic* · *Cancel run* |
| `protected path modified: {files}` | the file list with `+ − ~` per file and a diff link into the artifacts tree; a line naming what *Accept* does | *Accept changes* | *Retry* · *Skip story* · *Skip epic* · *Cancel run* |
| `harness misconfigured: …`, `no story file`, `ambiguous story file`, `unexpected status: …`, `harness exit {code}`, `gateway unreachable` | the condition, the file list where there is one, the log tail; **no Answer box** | *Retry* | *Skip story* · *Skip epic* · *Cancel run* |
| `plan stale: {file}` | the diff of the list file between the plan commit and the branch head | *Continue on the recorded plan* | *Cancel run* (and `start a new run` link) |
| `internal: {error}` | the exception line and log tail | *Retry* | *Skip story* · *Skip epic* · *Cancel run* |

- Other states: `RUN` — no banner, current step row marked, no Stop body. `ERR` (run `failed`) — banner red; the failing command and its last 40 lines; no action but `start a new run` (a link to New workflow pre-filled) — failed runs are terminal. `DON` — banner replaced by a one-line summary: progress, one compare link per epic, skipped stories and epics listed by id. `CAN` — banner grey, `cancelled by operator at …`.
- **Terminal session in progress** — the line under the command block reads `terminal session in progress · Answer, Continue, Skip and Retry disabled until Release — the run resumes by itself when the story file is done and the tree is clean`.

### 2.3 · Run diagram (`RunDiagram.dc.html`)
- Reached by the `DIAGRAM · DETAIL` toggle in the run's bar (query string `view=diagram`, survives reload). Same header meta line as 2.2; same alert banner rules.
- **Layout:** a left-to-right tree with orthogonal hairline connectors (`{colors.line-strong}`), square nodes on `{colors.surface}`. Column heads `RUN · EPICS · STORIES · STEPS` in `{typography.column-head}`. Root = the run (for an `initiative` run: the initiative; branch, token, progress). Level 1 = one node per epic from the plan (`epics[i]`), each holding its own `checkout · baseline` before and `push · link` after its stories; an `epic` run has one epic node; the first row `plan` sits between the root and the first epic. Level 2 = story nodes in `stories.yaml` order, grouped **by path**, never by story-id prefix. Level 3 = the story's sub-steps.
- **Node:** `{typography.row-title}` label, `{typography.meta}` kind or duration, chip + token right-aligned. A story node adds a `{typography.micro}` row of its sub-steps as words (`sync done · build done · verify — · commit —` and, when declared, `checkpoint`), never as coloured dots — a second chip on a node would be a traffic light. A `template` call that is not expanded (Templates screen) draws as one collapsed node with the callee's name and version. The current node is promoted to `{colors.text}` and carries the word `now` in `{typography.eyebrow}`; scheduled nodes read `QUE` in tertiary. No node carries more than one signal colour — the token is the signal.
- **Group token** (epic and story nodes), one rule: `ERR` / `BLK` / `CHK` if any child is, else `RUN` if any, else `SKP` when every child is skipped, else `DON` when all are done or skipped, else `QUE`. A cancelled run derives no group tokens; the root reads `CAN`.
- **Rendering:** the same backend graph as the Templates diagram, with a run's statuses bound and loops expanded; both are drawn left-to-right (the Templates diagram is no longer vertical). Read-only; clicking a node switches to DETAIL scrolled to that step's row by path.
- **Footer readout** under the tree: `step 15 of 22 · epic 1 · story 4-1 · build · blocked 2d 04h · 5/8 stories`.
- **States:** `RUN` — the running node green, one only. `BLK`/`CHK` — the stopped node amber; the banner above says why. `DON` — all nodes grey, each epic's `link` node `DON` with its compare link. Empty (run queued) — every node `QUE`, root says `waiting: …`.

### 3 · Projects (`Projects.dc.html`)
Two panes: list (name, repositories, runs, one amber/red count if any) and detail: title + meta (created, monthly spend, `log_prompt_content on/off`), **Context** (text + hint that it is written to `project-context.md` for every story), **Repositories** table (`repository · default · method · quality_gate_command · test_globs · clone check · status`) with *+ Add repository*; the `method` cell reads the version found, `missing`, or `outdated`, and a `missing`/`outdated` row carries *Initialise repository* (starts a `repo-init` run; the row then links to that run's card and, when done, to its compare link); a `failed` clone check reads `failed · new runs blocked` with *re-run check*. **Settings** kv (env vars: count, masked values; a plain line: `GitHub token and gateway key: instance settings`). **Runs on this project**. Bar actions: *Edit*, *Export trajectories* (downloads `trajectories.jsonl`, newest first; the hint says one line per done story). A repository without `quality_gate_command` shows `— none declared` and its status says `verify step will be skipped` — stated here, at configuration time.

### 3.1 · New project (`NewProject.dc.html`)
Form left: name, context, context file paths, env vars, `log_prompt_content` switch with its statement in secondary text, repositories (URL, default branch, package manager, `test_globs` with the default pre-filled, `install_command`, `quality_gate_command`, `unit_test_command`); no token field, one secondary line `credentials are instance settings (.env)`. **Clone check** readout right, live on save: per repository `ls-remote`, shallow clone (size, seconds), default branch, method version. A failure prints the git output verbatim in an inset block and a one-line fix; the project saves anyway and the failing repository reads `failed · new runs blocked`; a `missing` or `outdated` method reads `run Initialise repository after save`. The form keeps every value.

### 4 · Runs (`Runs.dc.html`)
Bar: project filter + status filter (`ALL · QUE · RUN · BLK · ERR · DON`). **Queue** section: engine queue readout (`pos · project · workflow · next step · waiting because · waiting`), reasons from a fixed set (`repository lock held by {run}`, `global concurrency, held by {runs}`, `running`, `waiting for your answer`), with the queue's own parameters in the section head (`concurrency {MAX_ACTIVE_RUNS} · one active run per repository · parked runs hold a slot`). A parked run appears with `—` position and `waiting for your answer` (hint: `not queued until then`). **History** table: `time · project · workflow · path · kind · harness · status · time · cost · trace`, one row per attempt, newest first, current rows promoted; harness, session and tokens empty on non-agent rows. Rows link to the run detail scrolled to that path. Pagination is SHOULD.

### 5 · Templates (`Templates.dc.html`)
Three columns: **versions list** (name, version, pinned-by count, `called by {name@v}` when a callee, read-only marker), **YAML editor** (line numbers, keys secondary, values primary, `uses:` kinds and `run:` in accent; the selected step highlighted), **Diagram** rendered from the backend graph (left-to-right like 2.3: node per step with kind eyebrow and gate word; `for_each` as a dashed group; `template` calls collapsed with callee name and version; agent nodes accent-bordered; declared human gates carry the word `human` and a `{colors.line-strong}` hairline, never amber) + **Inputs bound at start** table (type per input: `project | repository | string | path | enum | number | item`). Bar: validation readout (`valid · {time}` or `{n} errors`), *Validate*, *Save as vN+1*. Validation errors list `line · reason` under the editor; invalid YAML keeps the last valid diagram with the line `diagram from last valid version`. Saving never mutates a pinned version (directly or as a callee); the list explains this in a hint. Escalation edges are not drawn — they all go to *Needs you*. Nodes without a gate carry the word `unvalidated`.

## State vocabulary

| Token | Run | Step |
|---|---|---|
| `QUE` | enqueued, or waiting for a repository lock or a concurrency slot | `planned` (predecessor not done) or `queued` (next to run) — the word says which on hover / in the table |
| `RUN` | a step is executing | executing |
| `BLK` | any Stop of §4.6 except a checkpoint: blocked, verify failed, budget, timeout, push rejected / sync diverged, protected path, misconfigured, plan stale, internal | the step that stopped (`blocked` or `error`) |
| `CHK` | paused at `spec_checkpoint` (a status of the story step) or `done_checkpoint` (a planned checkpoint row) | the checkpointed row |
| `ERR` | `failed`, terminal: baseline non-zero, `on_fail: fail`, parked 30 days | `error` — inside a `BLK` run until retried or skipped |
| `DON` | every epic pushed | done |
| `SKP` | — | `skipped · already done`, `skipped · skipped by operator`, `skipped — no quality_gate_command`, `skipped · no command` — always the word, never green |
| `CAN` | cancelled by the operator (shown under Failed) | rows not yet run read `skipped` |

## Deltas from the 2026-08-25 spine, stated
1. Board columns are status, not pipeline stage (one dev loop, real concurrency).
2. No Notifications surface; "Needs you" column + rail count.
3. No G2/G3 pages; checkpoints live inside the run detail.
4. Answer box is the primary reply path (archive + re-plan with the answer as context — the in-place `## Human Answers` append was rejected at PRD review because build-auto preserves the old intent contract on a draft resume); the resume command is secondary.
5. Signal palette reduced to green / amber / red + greys.
6. New workflow is a page with pre-flight and the whole plan, replacing the G2 plan review.
7. Templates are editable YAML with a rendered diagram (the PRD's "editing is git" is relaxed; versions are immutable once pinned, callees included).
8. Board columns are five **equal fluid** columns filling 1440px (not the 08-25 spine's assumed fixed 232px + horizontal scroll); they still never collapse or size to content.
9. Dense tables (steps, runs history, repositories, the plan) are a **different component** from the five-column record row: they carry as many columns as the data has, keep the same type roles and hairlines, and the status token stays the only signal-coloured cell in a row.
10. Signal colour allowances beyond chip + token, made explicit: the rail's "n need you" count, a column header, the 2px alert-banner rule, an aged wait, the single warning/failure line in a readout, the login rejection line. Cards carry no coloured border and no coloured words — the token (and an aged age) is the only signal on a card.

## Deltas from the 2026-08-26 version, stated (2026-09-02)
11. **Run `ERR` is terminal and rare.** Every retryable stop is amber `BLK` with the step row `ERR`; the red run banner has no *Retry*. Reason: PRD FR-20 — `failed` runs are terminal, retry lives on `needs-you`.
12. **Stops are a table, not prose.** The run detail body and actions follow the PRD §4.6 Stop table one row each; new stops: sync diverged, timeout, push rejected, protected path (with *Accept*), misconfigured (no Answer box), plan stale, internal; new actions *Skip epic*, *Raise budget*, *Reject with a reason*.
13. **The plan is visible before and during the run.** "What will run" and the Steps table are the same planned rows, path-keyed, present from the start; the diagram groups by path, not by id prefix, and its root is the initiative.
14. **Credentials left the Project.** No token field, no per-project gateway key or budget; a plain line says they are instance settings. The Project gains `test_globs`, `install_command`, `log_prompt_content`, a method column with *Initialise repository*, and *Export trajectories*.
15. **Harnesses are a readiness list.** New workflow shows `enabled` / `disabled: {check}` per harness with a re-run control; a harness is never silently selectable.
16. **Compare links, not PRs.** Every copy that said `PR #` now says `link`; one per epic.
