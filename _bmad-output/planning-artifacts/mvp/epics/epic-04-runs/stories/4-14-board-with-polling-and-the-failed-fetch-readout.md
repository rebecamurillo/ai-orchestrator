## Intent

**Problem:** `/` is a permanent placeholder (`NOTHING REGISTERED` unconditionally). The Board
read model (`GET /runs?view=board&project_id=`, story 4-12) exists but nothing renders it.

**Approach:** Build the `Board` island (five status columns, cards, empty states, project
filter) plus the `$poll`/`$board` nanostores and a reusable `FailedFetch` full-surface
readout. `index.astro` keeps its existing SSR `GET /projects` gate (unchanged for the
zero-project case, which two frozen e2e tests pin) and mounts `Board` only when a Project
exists.

## Boundaries & Constraints

**Always:** Five columns always rendered, never collapsing (UX-DR7). `$poll` ticks 5s while
`counts.running > 0` else 30s; every response is one state swap, no CSS transition. A
non-2xx/network error on a poll replaces the whole Board surface with `FailedFetch` and
pauses polling until Retry succeeds. Exactly one signal colour per card (NFR-6); `skipped`/
`unvalidated`/`cancelled` are words, never green. The project filter is `?project=`, read at
load. `AppRail`/`FooterReadout`/`SurfaceBar`/`Shell` (`.astro`, container-tested with **no**
React renderer registered in `components.test.ts`/`shell.test.ts`) are left untouched — no
nested `client:load` component inside them.

**Block If:** none — the endpoint, its schema, and every binding rule needed to build this
screen already exist; no ambiguity requires an operator decision beyond the deferred bound
below (resolved here per the story's own instruction).

**Never:** widen/reshape `GET /runs?view=board`; the LIST toggle (rendered disabled, out of
scope, Epic 8); Run detail (`/workflows/:id`, 4.15) — the whole-card link only.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Mixed board | Cards in every column incl. one `cancelled` | 5 columns, right counts, fixed field order, `cancelled` under Failed as `CAN · cancelled` | — |
| Running present | `counts.running > 0`, page open 12s (fake timers) | polled at 5s; 30s once `running = 0`; each response is one swap, no transition | — |
| Poll fails | stub 500 on a poll | surface → `FailedFetch` (`GET /api/runs?view=board → 500`), polling paused | Retry re-fetches; success restores Board + polling |
| Stale response | poll N+1 resolves before poll N | poll N's late response is dropped | seq guard, mirrors `NewWorkflow.tsx` |
| No signal | no `needs_you`/`failed` cards | no amber/red pixel anywhere | — |
| Aged block | one `BLK` card, age > 48h | its token + its age are amber; nothing else is | — |
| Empty board | zero cards, ≥1 Project | `NOTHING RUNNING` + link `new workflow` | — |
| No project | zero Projects (SSR) | unchanged: `NOTHING REGISTERED`, `board-empty`, link `register a project to start` → `/projects` (frozen `login.spec.ts`) | — |
| Filtered | `?project=<id>` | filter active; request carries `project_id=<id>` | — |
| Many done/failed | `done`/`failed` column > 20 cards | render newest 20 (`age_seconds` asc), trailing "N more not shown" line | client-side cap only — the fetch itself is unbounded per 4.12 |

## Design Notes

**The `done`/`failed` bound (4.12's deferred decision, now resolved).** `board_view` never
sorts or bounds `done`/`failed` and story 4.12 explicitly deferred that call to this story.
`EXPERIENCE-v1.md`'s own Board mockup names the number: "LIST toggle: ... for when the board
has more than ~20 cards" — the design already anchors a ~20-card threshold for when a flat
list stops being enough. Since `?view=board` cannot be widened (frozen contract) there is no
cursor to page further with, so the cap is a *rendering* decision, not a fetch one: `Board.tsx`
renders the 20 most recent cards per `done`/`failed` column (`age_seconds` ascending) and a
plain trailing line stating how many more are not shown (never a link to LIST, which is out
of scope and disabled this epic). `queued`/`running`/`needs_you` are never capped — an
operator must always see everything that is active or needs them.

**Rail/footer/surface-count reactivity is DOM-patched by `Board.tsx`, not slotted through
`Shell`.** See Code Map: the four `.astro` shell primitives are rendered by
`AstroContainer.create()` with no renderer in two frozen unit test files, so a nested
`client:load` component inside any of them throws at that layer. Adding new optional slots
to thread a React island through `Shell` → `AppRail`/`FooterReadout`/`SurfaceBar` was
considered and rejected as unjustified blast radius across four shared, heavily-reused files
for what one screen needs; the chosen fix confines every change to `Board.tsx` and leaves
all four `.astro` files byte-for-byte unchanged. `shell.spec.ts`'s frozen `FOOTER` constant
(`'0 running · 0 queued / 0 need you / updated —'`, no `· refresh` suffix, checked with
`toHaveText` — exact match) proves the footer's own text never includes a refresh control;
"refresh" in the UX mockup is a separate control, which `Board.tsx` renders itself (calling
`forceTick()`) rather than adding to `FooterReadout`.

**No-project empty state text deviates from the brief, spine wins.** The brief's binding rule
says the empty state links to `/projects/new`; `tests/e2e/login.spec.ts` (frozen) asserts
`board-empty` contains `NOTHING REGISTERED` and a link named `register a project to start`
with `href="/projects"` — the exact copy the *current* `index.astro` placeholder already
uses. Per hard rule 1 the frozen test wins; this branch of `index.astro` is kept verbatim.

**Signal rule on an aged `BLK`/`ERR` card.** The card binding rule gives `BLK`/`ERR` (not
`CHK`) the 2px left rule, in the same signal colour as the chip+token (`StatusToken.astro`'s
existing `data-signal` mapping — one CSS custom property drives chip, word and rule). AC4's
"and nothing else is [amber]" is read as "no other card/column is amber", not as excluding
the same card's own chip/word/rule/age, which the attention-model table already groups as one
signal expressed in several places.

**A `?project=` deep link resolves the zero-project gate.** `GET /api/v1/projects` (the bare
list) answers unconditionally empty in the shared `make e2e-ui` stub (2.4/3.5's own frozen
constraint, restated for `/` by `shell.spec.ts`/`login.spec.ts`), so `board.spec.ts` cannot
reach the "≥1 Project" branch through the plain list at all. `index.astro` resolves a
`?project=<id>` link — the exact shape its own filter writes — through the non-list
`GET /projects/{id}` when the list itself is empty, `new.astro`'s own deep-link precedent
(4.13 Design Notes: "the same shape a real 'start a new run' link would land"). This is not
test-only behaviour special-cased into production code: it is the same resolution the New
Workflow screen already ships, applied to the one query parameter this screen's own filter
produces.
