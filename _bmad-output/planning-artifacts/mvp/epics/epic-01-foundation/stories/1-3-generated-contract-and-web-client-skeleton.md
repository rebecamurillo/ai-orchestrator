## Intent

**Problem:** backend-api publishes an OpenAPI document nobody exports, and the repository has no
second deployable at all. Without an exported contract and generated TypeScript, the first screen
would hand-write payload types that drift from Pydantic; without the proxy, an island would need
`ORCHESTRATOR_TOKEN` in the browser. `make openapi` and `make e2e-ui` still refuse.

**Approach:** Add `orchestrator.tools.export_openapi`, which builds the app with dummy settings —
no environment, no database — and prints the document with stable key ordering to
`contracts/openapi.json`. Scaffold `web-client/` (Astro 7 SSR on the Node standalone adapter,
React 19) whose only `fetch` callers are `src/api/server.ts` and `src/api/client.ts`, whose
`src/pages/api/[...path].ts` forwards `/api/*` to `${BACKEND_API_URL}/api/v1/*` with the bearer,
and whose types come only from `pnpm gen:api`. Turn `make openapi` and `make e2e-ui` from
refusals into gates, and fold `pnpm gen:api --check`, `pnpm lint` and `pnpm test` into `make lint`
and `make test`.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Export the contract | no `.env`, no database, empty environment | the OpenAPI document on stdout, keys sorted, one trailing newline | a build failure exits non-zero and leaves `contracts/openapi.json` untouched |
| Export twice | `make openapi; make openapi` | byte-identical `contracts/openapi.json` and `schema.d.ts` | N/A |
| Drift | `schema.d.ts` hand-edited, or the backend schema changed without regeneration | `pnpm gen:api --check` exits non-zero naming `src/api/schema.d.ts` | the on-disk file is never rewritten by the check |
| Proxy happy path | `GET /api/ping` on the Astro server | forwarded to `${BACKEND_API_URL}/api/v1/ping` with `Authorization: Bearer`, upstream status, headers and body returned unchanged | N/A |
| Proxy method and body | `POST /api/x` with a JSON body | method, body and `Content-Type` forwarded | N/A |
| Hop-by-hop headers | upstream answers with `Connection`/`Transfer-Encoding`/`Keep-Alive` | those headers are dropped from the response | N/A |
| Credential leak | any proxied response | no response header, and no byte of the built client bundle or served HTML, contains the token | N/A |
| Caching | any proxied response | `Cache-Control: no-store` | N/A |
| Island calls `fetch` | a temp file under `src/islands/` calling `fetch(...)` | eslint reports `no-restricted-globals` on that line | N/A |
| Island imports the server module | a temp file under `src/islands/` importing `../api/server` | eslint reports `no-restricted-imports` on that line | N/A |
| Smoke | `GET /` on `pnpm preview` | 200 with the text `web-client up` | N/A |
| Landed gates | `make openapi`, `make e2e-ui` | they run their tooling | neither prints `not available until story 1.3` |

## Spec Change Log

**A third new Makefile test module, `test_makefile_web_client.py`.** The plan named two new
modules, one per landed gate. `make lint` and `make test` also gained sub-gates this story
(`pnpm gen:api --check`, `pnpm lint`, `pnpm test`), and the module that asserts the sub-gates
of those two targets — `test_makefile.py` — is frozen and cannot be extended. Without a third
module, deleting `pnpm lint` from the recipe would leave eslint, prettier, `tsc` and
`astro check` unrun with `make lint` still green. Both mutations are checked: dropping
`pnpm lint`, and dropping the `--check` that keeps the drift gate from silently regenerating.

**`pnpm preview` runs `dist/server/entry.mjs`, not `astro preview`.** Astro 7's `astro preview`
starts a background daemon and returns; Playwright's `webServer` reads a command that exits as
a server that died, and a second run finds the first daemon still holding the port. The
standalone entry is the same process the container runs in 1.6, runs in the foreground, and
honours `server.host`. The brief's `webServer: { command: 'pnpm preview' }` is unchanged — only
what that script runs.

**The preview server binds `127.0.0.1` explicitly, and Playwright waits on a URL rather than a
port.** `localhost` resolves to both `::1` and `127.0.0.1`, so a stray process on either address
makes Playwright's port check refuse to start. A dev/preview server should be loopback-only in
any case; the container serves through `HOST`/`PORT` on the standalone entry and is unaffected.

**`src/api/client.ts` types itself with the generated `paths` minus backend-api's `/api/v1`
prefix.** The contract publishes `/api/v1/ping`; the browser reaches it at `/api/ping`, because
adding the version prefix is the proxy's job. The client applies a type-level key rename to
`paths` rather than a hand-written twin, so AD-3 holds — no payload type is written here — and
`/healthz`, which is not reachable through the proxy, correctly drops out.

**The bundle grep is a Playwright test, not a Vitest one.** A unit test cannot grep a build that
does not exist without either building (slow) or skipping when `dist/` is absent — a gate that
passes by disappearing. `make e2e-ui` is `pnpm build && pnpm e2e`, so `dist/` is always there
when Playwright runs.

**Playwright runs against a stub backend-api by default.** `tests/e2e/stub-backend.mjs` answers
the two routes the proxy specs need, so `make e2e-ui` requires no database and no running
backend. It also serves `/api/v1/echo-auth`, which deliberately reflects the credential it was
sent: nothing in this system does that, which is exactly why the proxy is shown to strip it
anyway. `E2E_BACKEND=real` points the same specs at a real backend-api, and was run that way
against the 1.2 stack during verification.

**eslint parses `.astro` with `astro-eslint-parser` alone.** `eslint-plugin-astro@3` requires
`eslint-plugin-jsx-a11y`, which declares support only up to eslint 9. The AD-1 restrictions are
core eslint rules and need no plugin; the fixture test proves they fire on `.ts`, `.tsx` and
`.astro` under all three restricted directories.

**`web-client/pnpm-workspace.yaml` is committed.** pnpm 11 refuses to run a dependency's install
scripts until the package opts in, and esbuild — reached through vite, and so through astro and
vitest — verifies its platform binary in one. Without `allowBuilds: esbuild: true` a fresh clone
fails at `pnpm build`.

**Review round 1 — eight patch findings, no loopback.** Reviewed inline (the three layers were
run in this session; the dispatching supervisor barred subagents). Applied: the proxy resolves the
requested path against the versioned base and refuses one that escapes it, so a `%2e%2e` segment
cannot reach backend-api's unversioned routes carrying the instance credential; `content-encoding`
and `content-length` are dropped from the response and `accept-encoding` from the request, since
the body is re-framed and already decoded; `E2E_BACKEND=real` without `ORCHESTRATOR_TOKEN` now
fails loudly instead of sending an empty bearer; `scripts/gen-api.mjs` takes `--contract` and
`--output` so `tests/unit/gen-api.test.ts` can drive the drift gate against a scratch file rather
than the repository's own; the bundle grep reads bytes rather than decoding as UTF-8; `lint.test.ts`
uses `fileURLToPath` rather than a file URL's `pathname`; `test_makefile_e2e_ui.py` asserts
Playwright's `testDir`. Two findings were deferred to `deferred-work.md`: the proxy's answer when
backend-api is unreachable, and repeated response headers being flattened.

`..%2Fhealthz` is **not** refused, and a test says so: `%2F` is a path separator to neither URL
parser, so it names one opaque segment inside the prefix. Refusing it would refuse legitimate ids
that contain an encoded slash.

## Design Notes

**Why the exporter builds settings with `model_construct`.** `make openapi` must not need `.env`,
and AD-20 fixes the number of places that know the settings contract at two (the module and
`.env.example`). A third table of dummy values in the exporter would be a third place. Pydantic's
`Settings.model_construct()` builds the object without validation and without reading the
environment; `create_app` only stores it on `app.state`, so nothing dereferences a field. If a
later story makes `create_app` read one, the exporter fails loudly with `AttributeError` rather
than exporting a wrong document.

```python
document = create_app(Settings.model_construct()).openapi()
stream.write(json.dumps(document, indent=2, sort_keys=True) + "\n")
```

**Why the Makefile writes through a temporary file.** The brief's `… > contracts/openapi.json`
truncates the committed contract before the exporter runs, so a failed export destroys it. The
exporter takes `--output` and replaces the file atomically only after the whole document is built;
stdout stays the default so the brief's command still works by hand.

**Why `astro:env/server` is aliased in Vitest.** `src/api/server.ts` is the one module that reads
the token, and testing it is the only way to prove the bearer is added. The virtual module exists
only inside an Astro build, so `vitest.config.ts` aliases it to
`tests/stubs/astro-env-server.ts`, which exports placeholder constants. The real module is still
type-checked, by `astro sync` + `tsc --noEmit` + `astro check` inside `pnpm lint`.

**Where the bundle grep lives.** A Vitest unit test cannot grep a bundle that has not been built
without either building (slow) or skipping when `dist/` is absent (a gate that passes by
disappearing). `make e2e-ui` is `pnpm build && pnpm e2e`, so `dist/` always exists when Playwright
runs: `tests/e2e/no-credential.spec.ts` greps `dist/client/**`, the served HTML, and every
response header for the token.
