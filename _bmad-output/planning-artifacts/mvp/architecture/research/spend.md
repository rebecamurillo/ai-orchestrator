# Per-Run / per-attempt spend on open-source LiteLLM — verified 2026-09-02

- Headers recorded on `LiteLLM_SpendLogs` without premium: `x-litellm-end-user-id` → `end_user` (also `LiteLLM_EndUserTable.spend`); `x-litellm-session-id` (or `x-litellm-trace-id`) → `session_id` (indexed); `x-litellm-tags: a,b` → `request_tags` JSON. No `premium_user` check on populating them (spend_tracking_utils.py, litellm_pre_call_utils.py). https://docs.litellm.ai/docs/proxy/request_headers · https://docs.litellm.ai/docs/proxy/customers
- Endpoints, not premium: `GET /spend/logs/v2?end_user=&session_id=&start_date=&end_date=&page=&page_size=` (also `api_key, user_id, request_id, team_id, model, status_filter`); `GET /customer/info?end_user_id=` → cumulative spend; `GET /spend/tags`, `GET /global/spend/tags?tags=`. Premium: `/global/spend/report` and `/key|user|team|organization/spend/report`. `GET /spend/logs` (v1) has no end_user/tag filter. https://github.com/BerriAI/litellm/blob/main/litellm/proxy/spend_tracking/spend_management_endpoints.py
- Enterprise-labelled, avoid: `x-litellm-spend-logs-metadata`.
- Langfuse alternative: cost is re-inferred from model names (LiteLLM's OTel export sets `gen_ai.cost.*` attrs Langfuse ignores); `GET /api/public/v2/metrics` by sessionId/tags works but lags and needs model price definitions for local aliases. Weaker; not chosen.
- Decision (AD-11): `x-litellm-end-user-id = run_id`, `x-litellm-session-id = attempt_id`, tags `run:,attempt:,story:,harness:,project:`; `Gateway.spend_for_attempt` sums `GET /spend/logs/v2?end_user=&session_id=`. Day-1 check: coexistence with `langfuse_session_id` (Open at handoff 5).
