# DBOS Transact (Python) — verified 2026-09-02

- `dbos` 2.31.0 (PyPI, 2026-08-25), Python >=3.10 (classifiers to 3.14). Depends on `psycopg[binary]>=3.1`, `sqlalchemy[asyncio]>=2.0.43`.
- System DB: `system_database_url` (Postgres recommended; SQLite default); tables in schema `dbos` (`dbos_system_schema` config) of whatever DB the URL points at — sharing the app DB is allowed; multiple apps distinguished by `name`. https://docs.dbos.dev/python/reference/configuration · https://docs.dbos.dev/explanations/system-tables
- Queues: `Queue(...)` deprecated → `DBOS.register_queue(name, *, global_concurrency, worker_concurrency, limiter, partition_concurrency, partition_worker_concurrency, partition_limiter, polling_interval_sec, on_conflict)`; enqueue with `with SetEnqueueOptions(queue_partition_key=..., priority=..., deduplication_id=...): DBOS.enqueue_workflow("q", fn, ...)`; `DBOS.listen_queues([...])` before launch. https://docs.dbos.dev/python/reference/queues
- Introspection: `DBOS.list_workflow_steps(workflow_id) -> [StepInfo{function_id, function_name, output, error, child_workflow_id, started_at_epoch_ms, completed_at_epoch_ms}]`; `DBOS.get_workflow_status`, `DBOS.retrieve_workflow`, `DBOS.list_workflows(status=, queue_name=, parent_workflow_id=, attributes=, ...)`. Inside a step: `DBOS.workflow_id`, `DBOS.step_id` (int, unique within workflow), `DBOS.step_status`. `(workflow_uuid, function_id)` is the natural key of `dbos.operation_outputs`. UNVERIFIED: that `DBOS.step_id` == `function_id` exactly (treat as the same integer; confirm day 1).
- Metadata: `SetWorkflowID(id)`, `SetWorkflowAttributes({...})` (JSON, filterable on Postgres), `DBOS.update_workflow_attributes`. https://docs.dbos.dev/python/tutorials/workflow-management
- Child workflows: `DBOS.start_workflow(fn, ...)` inside a workflow → child with derived id; linkage `workflow_status.parent_workflow_id` + `operation_outputs.child_workflow_id`; `list_workflows(parent_workflow_id=...)`.
- Messaging: `DBOS.send(dest_id, msg, topic)`, `DBOS.recv(topic, timeout_seconds)` (None on timeout); `set_event/get_event`; `DBOS.sleep` durable; `SetWorkflowTimeout`; `DBOS.cancel_workflow(id, cancel_children=)`, `resume_workflow`, `fork_workflow(id, start_step, ...)`. https://docs.dbos.dev/python/tutorials/workflow-communication
- Steps: `@DBOS.step(retries_allowed=False, max_attempts=3, interval_seconds, backoff_rate, should_retry, preemptible, timeout_seconds)`; `@DBOS.workflow(max_recovery_attempts=100)`. Async `async def` workflows/steps supported (`start_workflow_async`, `enqueue_async`); `timeout_seconds`/`preemptible` async-only. Recovery: PENDING workflows resume from last completed step on restart; completed steps never re-run; `application_version` must match (default = hash of workflow source). https://docs.dbos.dev/production/workflow-recovery
- DB access: `@DBOS.transaction` legacy sync-only; recommended `SQLAlchemyDatasource` / `AsyncSQLAlchemyDatasource` (`from dbos import ...`, `.create(database_url, engine=...)`, `ds.sql_session()`), URLs `postgresql+psycopg://`. https://docs.dbos.dev/python/reference/datasources
- Scheduling: `@DBOS.scheduled(cron)` labelled deprecated → `DBOS.create_schedule(schedule_name=, workflow_fn=, schedule=, ...)`. https://docs.dbos.dev/python/tutorials/scheduled-workflows
- FastAPI: `DBOS(config=...)`; `DBOS.launch()` before `uvicorn.run`; `DBOS.destroy()`. (`fastapi=` kwarg seen in examples, not in the current class reference — UNVERIFIED.) Admin server deprecated (`run_admin_server` default False). CLI: `dbos workflow list|get|steps|cancel|resume|fork`, `dbos workflow queue list`. https://docs.dbos.dev/python/reference/cli
