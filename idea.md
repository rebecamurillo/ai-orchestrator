❯ /bmad-forge-idea I need to build like an OS for a ai agents workflows for company. First scénario is issue to PR, or more like idea/feature to PR. The idea is to have an orchestrator that handles software engineering processes for multiple projects (with one or more repositories pre project).  I will be using the BMAD method for skills execution. The orchestrator will trigger deterministic actions (git checkout, run tests, etc) and trigger prompts for ai agents, an agent is validated by checking its output file or files, done by orchestrator. If there is an issue with an agent (blocked with open questions), then human needs to be informed (through UI first, then next version through mattermost). The orchestrator backend will be in python with postgresql db and DBOS for workflows execution, and workflows will be saved in yaml file in format CNCF Serverless Workflow DSL. A front-end client will allow user to onboard a new project and its repository (with strategy and business info per project, communication and architecture charts, etc. Everything necessary for agents to know context for the project). Front-end would also allow user to view the predefined workflows and update them (same ux as Kestra https://kestra.io/). A wokflow is generic, with some variables to be overwritten that depend on repositories (like unit test run or E2E test run command lines per repo), and can contain actions like run a script, run a command line shell, run an agent. Agents are triggered in print mode (non interactive) with claude or codex (more harnesses to come later), orchestrator saves the session id for each task, in case session needs feedback or human needs to contact again.  The harnesses are setup to connect with Litellm gateway. The orchestrator and the harnesses running the tasks will be setup to send information to Langfuse for monitoring, with the same trace id. First PoC should be in one docker container that has all the tooling necessary to run the command lines and scripts (Git shell, claude, codex, install skills and agents for all harnesses, etc, with necessary environment variables). Once this is stable, we will think about scaling to multiple docker containers.
