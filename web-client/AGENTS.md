# AGENTS.md — web-client

Astro 7.2 (`output: 'server'`, `@astrojs/node` standalone) · React 19 islands · nanostores · openapi-fetch · CodeMirror 6 · @dagrejs/dagre · Vitest · Playwright · pnpm · Node 24. Read the root `AGENTS.md` first.

## Layout — where a change goes

```text
src/pages/                 one .astro page per screen: login, index (Board), runs/[id], runs, projects, templates
src/pages/api/[...path].ts proxy: forwards /api/* to $BACKEND_API_URL/api/v1/* with the bearer (AD-1)
src/api/server.ts          server-only: reads `astro:env/server`; the only place the token is read (AD-1)
src/middleware.ts          cookie guard (`orch_session`) → 302 /login (AD-4) — story 1.5
src/actions/               Astro Actions for form posts (login, project save, template save, run start)
src/islands/               React islands: Board, RunDetail, RunDiagram, TemplateEditor, ProjectForm, NewWorkflow
src/components/            static Astro components on the instrument-dark tokens (DESIGN.md)
src/stores/                nanostores: polling interval, session, board filters
src/api/schema.d.ts        GENERATED by `pnpm gen:api` — never edited
src/api/client.ts          openapi-fetch client with baseUrl '/api'
scripts/gen-api.mjs        `pnpm gen:api` and its `--check` drift gate
tests/unit/                vitest (islands with React Testing Library, stores, pure helpers)
tests/e2e/                 playwright; webServer = `pnpm preview`; backend stubbed unless E2E_BACKEND=real
tests/stubs/               doubles for Astro virtual modules that exist only inside a build
```

Directories with no file yet are created by the story that needs them; the layout above is
where a change goes, not a claim that every path already exists.

## Rules specific to this component

- **The browser never talks to backend-api** (AD-1). Islands fetch `/api/...` on the same origin; the proxy adds the bearer. No `BACKEND_API_URL` or token in client code (`astro:env` `context: 'server'`).
- **Types come from the contract** (AD-3). `pnpm gen:api` regenerates `src/api/schema.d.ts` from `../contracts/openapi.json`; `pnpm gen:api --check` runs in `make lint`. `src/api/client.ts` strips backend-api's `/api/v1` prefix from the generated `paths` at the type level, because that prefix is what the proxy adds — it writes no payload type of its own.
- **One polling loop** (FR-24): the `$poll` store ticks every 5 s while any Run is running, else 30 s; islands subscribe with `useStore`. Updates are a state swap with no animation; a failed fetch renders the full-surface readout with the failed request and a retry control.
- **Graph rendering only** (AD-15): `RunDiagram` and the template diagram receive `{nodes, edges, groups}` from the API, lay out with dagre, render SVG. No YAML parsing in the browser; the YAML editor only edits text and calls `/templates/{name}/validate`.
- **Status is a word token** with at most one signal colour per card or row (NFR-6). Tokens: `QUE RUN BLK CHK DON ERR CAN SKP`. `skipped` / `unvalidated` are plain words. A screen with nothing needing the operator has no amber or red pixel.
- **Copy** states facts and mechanisms (NFR-8): the Answer box says which file is archived where and that the story is re-dispatched.
- Islands are `client:load` only where the page cannot work without them; static content stays in `.astro` components. Props across the island boundary must be serialisable.

## Commands

```bash
pnpm install --frozen-lockfile
pnpm dev                      # astro dev on 127.0.0.1:4321 (needs BACKEND_API_URL + ORCHESTRATOR_TOKEN)
pnpm gen:api                  # regenerate src/api/schema.d.ts from ../contracts/openapi.json
pnpm gen:api --check          # fail if it is out of date; runs inside `make lint`
pnpm lint                     # astro sync + astro check + tsc --noEmit + eslint + prettier --check
pnpm test                     # vitest
pnpm build && pnpm preview    # node standalone build, then the built server in the foreground
pnpm e2e                      # playwright (run `pnpm exec playwright install chromium` once)
```

`pnpm preview` runs `dist/server/entry.mjs` rather than `astro preview`, which in Astro 7
starts a background daemon and returns — the same process the container runs, and one that
Playwright's `webServer` can supervise.

## Checkable limits

- A component file ≤ 300 lines; islands ≤ 5 props; no inline styles (tokens via CSS variables only).
- Every island has a unit test; every page has one Playwright smoke test; the Board and Run detail have a "needs you" scenario test.
